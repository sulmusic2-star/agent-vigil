# Hosted proof network threat model

## Overview

This model covers the optional Cloudflare Worker/D1 service in `services/proof-network` and its root CLI upload client. The primary assets are: integrity of signed compatibility records and broken-to-fixed bindings; publisher and administrator authority; lifecycle privacy; chronological first-100 sampling integrity; availability of public search/API pages; and the distinction between technical telemetry, genuine demand, payment, and revenue.

The service is prepared locally and disabled by default. Cloudflare, D1, Web Crypto, DNS/TLS, the operator's account, registered publisher keys, administrator token, issuing/HMAC keys, and independently reviewed release configuration remain trusted. A valid proof signature establishes record integrity under its key; publisher identity exists only because the operator registered that key through a separate trusted process. A `SAFE` record remains bounded evidence, not universal compatibility.

## Threat model, trust boundaries, and assumptions

- **Public reader boundary:** anyone may control search parameters, record hashes, conditional headers, and a pseudonymous rate-limit token. Responses must escape attacker-controlled proof fields, keep JSON typed, avoid write-capable CORS, and never render corrected, taken-down, revoked, or inactive evidence as an active verdict through direct, search, API, sitemap, resolution, or badge surfaces.
- **Publisher boundary:** proof bodies and acquisition facts are attacker-controlled until exact schema, hash, Ed25519 signature, active-key registration, chronology, and replay checks pass. A frequency publisher cannot submit eligibility, exclusion reasons, inspection state, handles, or sequences. Embedded public keys are not an identity root.
- **Acquisition-adapter boundary:** an independently registered, version-bound adapter signs the exact publisher/acquisition facts while the artifact state is `UNOPENED`. Its key is a distinct duty from publisher and operator keys. Missing, stale, future, revoked, wrongly bound, or replayed attestations create a counted server exclusion or are rejected; they cannot create an included row.
- **Operator/head boundary:** a third Ed25519 duty signs short-lived export manifests, current heads, and chunks. Consumers pin its SPKI outside publisher-controlled corpus bytes and retrieve the head through a trusted current-state channel. The offline verifier rejects missing, future, expired, wrong-key, rollback-mismatched, or stale manifest/head combinations and never turns an unsigned static corpus into PASS.
- **Administrator boundary:** the bearer token can register/suspend/revoke publishers, moderate records, revoke anonymous credentials, record evaluation state, and export telemetry. Compromise is high impact. Admin requests require TLS, rate limiting, a separate strong token, and should later sit behind additional access controls.
- **Anonymous installation boundary:** a server-issued capability plus request HMAC prevents another party from altering or replaying a known event and prevents one credential from claiming a different installation. Registration is still anonymous and therefore Sybil-susceptible. Its records are always `UNVERIFIED_TELEMETRY`, never an R0 denominator or commercial gate. Organization events are rejected until authenticated tenant linkage exists.
- **D1 ordering boundary:** server time, a UUID handle, and an autoincrement sequence are authoritative for receipt order. Registration must precede the adapter-authorized artifact-access grant, which must precede evaluation. Append-only authority/grant/stop tables, unique keys, and serialized all-row/included/component triggers protect ordinary concurrency; D1/account compromise remains out of scope.
- **CLI boundary:** record/event files, credential files, public-key files, endpoint values, server responses, and network failures are untrusted. The client requires explicit consent, verifies public records locally with a pinned key, uses HTTPS except loopback, refuses redirects, caps responses, never prints server bodies/URLs/secrets, and writes credentials owner-private on POSIX.
- **Privacy boundary:** public proofs intentionally reveal public component/version/artifact commitments and signer identity. They omit source, prompts, transcripts, commands, paths, environment, private repository/org identity, and raw receipt/canary output. Users must still review public component names and public canary IDs before consenting.

The service does not prove artifact provenance, signer host integrity, completeness of private evidence, genuine uniqueness of an anonymous installation, human identity, organization identity, adoption, payment, or revenue. Cloudflare edge logs and account-level products are outside application D1 controls and must be configured separately not to retain sensitive request data.

## Attack surface, mitigations, and attacker stories

- **Forged proof or resolution:** reject unknown fields, wrong canonical hashes, malformed/noncanonical key material, bad Ed25519 signatures, inactive/unregistered keys, stale/future evidence, missing referenced entries, inconsistent baseline/runner/signer/chronology, and conflicting idempotent content.
- **Publisher-key compromise:** append-only status events can suspend/revoke the key; public reads stop serving inactive publishers. Existing bytes remain for audit. A replacement is not silently substituted.
- **Stored/reflected XSS or terminal control:** proof schemas bound text and HTML renderers escape dynamic data under a restrictive CSP. CLI diagnostics suppress arbitrary exception text. JSON/SVG-adjacent badge data is typed and uses `nosniff`.
- **SQL injection and query abuse:** D1 queries use prepared bindings. Search values, limits, hashes, timestamps, enums, body sizes, encodings, and content types are bounded. Wildcards are escaped.
- **Replay/idempotency abuse:** proof hashes, event UUIDs, signed publisher request UUIDs, registration idempotency UUIDs, and exact body commitments detect conflicts. Publisher and lifecycle authenticated requests have a five-minute window. Frequency request replay must match both publisher and canonical proposal bytes.
- **Telemetry inflation:** registration is edge-rate-limited and each event is HMAC-bound to the server-issued installation. Changing an installation ID, request body, scope, channel, external/demo classification, or request UUID fails. An attacker may still register many anonymous installations through distributed sources, so the export is explicitly Sybil-susceptible and gate-ineligible.
- **Forged organization/commercial activity:** the anonymous route rejects every organization-scoped and organization-only event. Billing identifiers are not in this contract. Only a future authenticated tenant/provider ledger may establish organization, payment, entitlement, refund, or renewal facts.
- **First-100 selection manipulation:** the server derives every eligibility reason from authenticated acquisition facts and the trusted-adapter result. D1 records even missing-adapter exclusions before inspection; exact four-field deduplication and the lowercase global component/sample caps are database-enforced; excluded rows cannot receive evaluations. Publisher-supplied decision/reason fields fail exact-schema validation, distinct fake `DUPLICATE_PAIR` claims cannot enter the contract, and post-inspection acquisition is outside the trusted adapter state. Evaluation cross-fields are enforced in the Worker, schema, D1, and offline verifier.
- **Stale moderation replay or export surgery:** every manifest and current head binds the exact raw/provenance byte hashes, registration, monotonic publisher checkpoint, canonical publisher/adapter authority states, stop events, and hash-chained chunk descriptors. The verifier reconstructs all ordered rows from signed chunks and rejects omission, duplication, reordering, tampering, key-duty reuse, expired/future documents, or an older ACTIVE envelope paired with the current REVOKED head. Current REVOKED authority quarantines the row. Export assembly fails if its before/after database marker changes.
- **Denial of service/storage exhaustion:** route-specific body limits, content-encoding rejection, per-key/install/edge/public-read rate limits, bounded queries, result caps, and disabled-by-default flags constrain abuse. Frequency exclusions count toward concurrency-safe 1,000 global, 500/channel, and 400/publisher limits; the refusal is represented by a unique append-only stop event and signed into the export. Account-level quotas/WAF and incident procedures remain deployment prerequisites.
- **Moderation abuse/history rewriting:** original records are immutable. Moderation is append-only state; correction requires an existing same-component replacement. Search excludes corrected/taken-down/revoked rows; direct and API trust representations return unavailable; corrected badges are neutral and link only to the replacement. RESTORE is the explicit current-state transition that can make an original record active again.
- **Secret leakage:** secrets are Worker bindings or owner-private credential files, not code/config. Application logs omit bodies, queries, identifiers, IPs, headers, and exception messages. Admin/credential responses use `no-store`. Operators must separately protect Cloudflare access, CI output, shell history, backups, and local credential directories.

## Severity calibration

- **Critical:** remote admin authorization bypass; exposure of Worker secrets or lifecycle installation secrets at scale; SQL path allowing arbitrary publisher registration/moderation; a flaw that accepts unsigned/tampered `SAFE` evidence as registered proof; cross-tenant access once authenticated Team data exists.
- **High:** stored XSS on public proof pages; accepting a broken-to-fixed resolution that does not bind the same baseline/runner/signer; silently counting forged anonymous/org events as genuine demand gates; first-100 ordering or cap bypass that enables cherry-picking; serving revoked evidence as active.
- **Medium:** practical rate-limit bypass causing material availability/storage cost; cache/CORS behavior disclosing a moderated body; idempotency collision that changes a stored event; retention/logging that preserves forbidden operational identifiers without public exposure.
- **Low:** bounded unauthenticated search errors, inaccurate cosmetic badge text that cannot change signed evidence, missing non-sensitive cache optimization, or local developer inconvenience with no integrity/privacy consequence.

Any material false-compatible result, privacy incident, key compromise, forged gate metric, or frequency-ledger integrity failure stops the affected ingestion lane. Rollback disables flags and appends revocation/correction state; it never deletes or rewrites signed history.
